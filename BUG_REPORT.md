## High severity

### 1. Full Codex request payload logged at INFO

- **File:** `src/api/endpoints.py:348`
- **Summary:** `logger.info(f"Codex request input: {request.input!r}, model=...")` prints the complete user input (and any embedded tool args) without sanitization.
- **Concrete failure scenario:** A user sends proprietary code or PII in `/v1/responses`; the proxy emits it to stdout and any log shipper, causing sensitive-data exposure.
- **Existing tests:** `tests/codex/test_codex_request.py` does not assert log output.

### 2. OpenAI error response bodies logged without redaction

- **File:** `src/core/client.py:400-405`
- **Summary:** `_log_openai_error` writes `response.text` and `error.body` to `logger.error` verbatim.
- **Concrete failure scenario:** An upstream 400/422 body can echo request messages or provider hints containing API keys/prompts; this surfaces them in proxy logs.
- **Existing tests:** `tests/test_client_key_policy.py` covers key header policy, not log redaction.

### 3. SSRF via `/v1/models` listing against attacker-controllable `base_url`

- **File:** `src/core/client.py:407-431` and `src/api/endpoints.py:1417-1423`
- **Summary:** `list_models` concatenates `self.base_url` and calls `urllib.request.urlopen`. There is no allow-list, no SSRF guard, and no URL validation.
- **Concrete failure scenario:** An operator (or compromised `.env`) sets `OPENAI_BASE_URL=http://169.254.169.254/latest/`. `/v1/upstream-models` and `/v1/models` fetch cloud metadata, leaking IAM credentials.
- **Existing tests:** `tests/test_upstream_models.py`/`test_upstream_models_catalog.py` mock the client and do not exercise URL validation.

### 4. Regex "unquoted property" JSON repair mutates string values

- **File:** `src/api/endpoints.py:1318-1329`
- **Summary:** `parse_flexible_events` uses `re.sub(r"([{,]\s*)([a-zA-Z_][a-zA-Z0-9_]*)(\s*:), ...)` to quote property names. The regex does not distinguish string content from object structure.
- **Concrete failure scenario:** A client sends `{"data": "x: {a:1}"}`. The regex turns the inner `{a:1}` into `{"a":1}` inside the string value, producing mutated/wrong data and potentially arbitrary log structures.
- **Existing tests:** `tests/test_log_rotation.py` is gated behind `RUN_PROXY_INTEGRATION_TESTS` and does not cover string-mutation cases.

### 5. Hard-coded relative log path with no path control

- **File:** `src/api/endpoints.py:1384`
- **Summary:** `/api/event_logging/batch` writes to a literal relative path `Claude-proxy.log` in the current working directory. No log directory config, no sanitization.
- **Concrete failure scenario:** A deployment starts the proxy from a writable directory; an attacker who can create a symlink `Claude-proxy.log -> /etc/passwd` or source files can redirect log appends to overwrite arbitrary files.
- **Existing tests:** Same as #4.

## Medium severity

### 6. Fake Anthropic-dated model aliases can confuse clients

- **File:** `src/api/endpoints.py:1454-1477`
- **Summary:** The `/v1/models` endpoint advertises aliases such as `claude-sonnet-4-6` and `claude-opus-4-7` with Anthropic-style date suffixes, mapping them quietly to arbitrary backend models.
- **Concrete failure scenario:** A Claude Code client picks `claude-opus-4-7`, expects Anthropic Opus 4.7, but the proxy routes to a different Nebius model, silently changing quality/privacy/compliance posture.
- **Existing tests:** `tests/test_upstream_models.py` checks shape but not alias semantics.

### 7. Ensemble hedge race has unbounded upstream blast factor

- **File:** `src/ensemble/engine.py:247-253`, `src/core/client.py:192-271`
- **Summary:** `run_hedge_race` spawns N parallel candidate requests, each of which internally retries up to `max_retries` times. There is no race-level budget, so one user request can generate `N * (max_retries + 1)` upstream calls.
- **Concrete failure scenario:** A user sets 5 ensemble models with `max_retries=2`. A single backend-routed prompt produces up to 15 upstream completions, burning quota and increasing rate-limit exposure.
- **Existing tests:** `tests/test_ensemble.py` tests selection logic but not retry/retry-count amplification.

### 8. Search loop can consume unbounded tokens on a broken backend

- **File:** `src/conversion/server_tools.py:126-171`
- **Summary:** `run_search_loop` uses `max(1, config.server_search_max_iters)` but both the loop and the underlying chat completion have their own retries. A backend that always returns search tool calls causes repeated search+LLM turns.
- **Concrete failure scenario:** A misconfigured backend returns a search tool call every turn; `run_search_loop` runs many iterations, each calling Tavily + the backend, until the outer request times out.
- **Existing tests:** `tests/test_server_tools.py` tests the happy path but does not inject an always-search backend.

### 9. Unexpected exceptions in client lose traceback/type

- **File:** `src/core/client.py:269-270`, `src/core/client.py:333-335`
- **Summary:** A broad `except Exception` wraps the exception in `HTTPException(status_code=500, detail=f"Unexpected error: {str(e)}")`, discarding the original exception type and traceback.
- **Concrete failure scenario:** A `TypeError` or custom SDK failure is surfaced as a generic 500 string, making root-cause analysis harder and masking contract bugs.
- **Existing tests:** `tests/test_cancellation.py` covers cancellation, not generic exception wrapping.

### 10. Ensemble approval `choose` has no session-scoped authorization

- **File:** `src/ensemble/approval.py:50-61` and `src/api/endpoints.py:287-303`
- **Summary:** `approval_store.choose` only validates that the `request_id` is pending and the candidate index is valid. It does not check that the caller owns the request/session.
- **Concrete failure scenario:** User A has a pending approval race. User B (or any dashboard viewer with the key) calls `/api/observability/ensemble/choose` with A's `request_id` and forces a worse candidate output.
- **Existing tests:** `tests/test_session_ensemble_routing.py` covers routing/headers, not approval authorization.

## Low severity

### 11. `/health` exposes auth configuration details

- **File:** `src/api/endpoints.py:1207-1213`
- **Summary:** The unauthenticated health endpoint returns whether `openai_api_key` is set, whether client key validation is enabled, and that client keys are ignored.
- **Concrete failure scenario:** An external scanner calls `/health` and learns the proxy's auth posture (key configured, validation off), helping focus further attacks.
- **Existing tests:** `tests/test_main.py` checks health shape but not information leakage.

### 12. Session forwarder target parsing trusts arbitrary strings

- **File:** `scripts/session_forwarder.py:76-80`
- **Summary:** The forwarder parses the `target` argument with `urlparse(f"http://{self.target}")`; a target string containing a path is mishandled, and all traffic is blindly forwarded to whatever it resolves to.
- **Concrete failure scenario:** An installer or user passes `target=attacker.com:80/api`. `parsed.netloc` becomes `attacker.com:80/api`, host header is wrong, traffic leaves the intended upstream, or errors silently.
- **Existing tests:** `tests/test_session_forwarder.py` uses `localhost:8083` and does not validate target parsing edge cases.

### 13. Client `metadata.user_id` is forwarded upstream unvalidated

- **File:** `src/conversion/request_converter.py:701-708`
- **Summary:** `metadata_user_id` from the client request is sent to the backend as both `user` and `prompt_cache_key` with only a 256-char length truncation.
- **Concrete failure scenario:** A malicious client sets `metadata.user_id` to a value designed to poison prefix-cache affinity or trigger backend parsing bugs; it is accepted verbatim and used for upstream routing.
- **Existing tests:** Not covered by unit tests.

### 14. System-prompt supplements are appended without boundary checks

- **File:** `src/conversion/request_converter.py:560-617, 719-742`
- **Summary:** Computer-use and web-search nudges are concatenated to the first system message with `+= "\n" + ...`, treating existing content as trusted text.
- **Concrete failure scenario:** If upstream `system` content contains role delimiters or injection markers, the appended instructions can shift the system/user boundary and confuse the backend model.
- **Existing tests:** Not covered by unit tests.

### 15. Server-side search query is sent to Tavily unvalidated

- **File:** `src/conversion/server_tools.py:151-155, 266-270`
- **Summary:** Tool-argument query strings are inserted into the Tavily payload and logged with `!r` but are not validated, escaped, or length-limited.
- **Concrete failure scenario:** A model emits a query containing control characters or newlines; the query is logged and sent verbatim to Tavily, potentially leaking context or triggering provider-side issues.
- **Existing tests:** `tests/test_server_tools.py` covers happy path only.

### 16. Ensemble latency tie-break can raise `ValueError`

- **File:** `src/ensemble/engine.py:293-294`
- **Summary:** In the score-tie branch, `min(c.latency_ms for c in tied if c.index != best.index)` assumes at least one other tied candidate exists. After a judge overrides the winner, `best in tied` can be true while the generator over `tied` excluding `best` is empty.
- **Concrete failure scenario:** A judge returns a candidate that is the sole remaining member of `tied`; `min()` over an empty iterable crashes the ensemble race with `ValueError`.
- **Existing tests:** `tests/test_ensemble.py` does not cover judge tie-break edge cases.

### 17. Codex namespace tool flattening has collision-prone names

- **File:** `src/codex/tools_compat.py:320-354`
- **Summary:** Proxy name is built as `f"{namespace}{original_name}"` with no separator; different `namespace + name` pairs can collide.
- **Concrete failure scenario:** `namespace="abc", name="def"` and `namespace="ab", name="cdef"` both flatten to `abcdef`; `remap_tool_calls_back` resolves both to whichever spec was registered last, returning the wrong original tool name.
- **Existing tests:** `tests/codex/test_tools_compat.py` may cover basic flattening, not collision cases.

## Low severity / additional findings

### 18. `src/models/openai.py` is empty

- **File:** `src/models/openai.py:1`
- **Summary:** The file contains no symbols but exists in `src/models/`.
- **Concrete failure scenario:** Any future or third-party code importing `src.models.openai.*` will succeed at import time but raise `AttributeError` at runtime; no current code references it.
- **Existing tests:** None.

### 19. SSE prefix strip length is off-by-one-ish

- **File:** `src/conversion/server_tools.py:211`
- **Summary:** `stripped[len("data:"):].strip()` removes 5 characters (`data:`), but OpenAI SSE lines are `data: ` (6 chars with trailing space). JSON is whitespace-tolerant, so behavior is functionally correct for well-formed lines, but malformed lines starting `data:x` strip one extra character.
- **Concrete failure scenario:** A backend emits `data:{"x":1}` (no space after colon); `len("data:")` removes the colon, producing malformed JSON.
- **Existing tests:** None.

### 20. `tool_block_counter` is incremented but never read

- **File:** `src/conversion/response_converter.py:641`
- **Summary:** `tool_block_counter` is dead bookkeeping; any future code relying on it will compute incorrect indices for parallel tool calls.
- **Concrete failure scenario:** Future refactor uses `tool_block_counter` to assign block indices; multi-tool-call turns produce duplicate/conflicting indices.
- **Existing tests:** None.

### 21. Codex search tool stripping uses hard-coded names and ignores non-configured Tavily

- **File:** `src/codex/request_converter.py:216-220, 240-255`
- **Summary:** `web_search`/`websearch` calls and their results are stripped from conversation history even when Tavily is not configured.
- **Concrete failure scenario:** A client defines a custom `web_search` tool with unrelated parameters; the proxy drops its calls and results, breaking the backend tool-calling contract.
- **Existing tests:** None.

### 22. Streaming text/thinking block transition can leave text block open

- **File:** `src/conversion/response_converter.py:986-993`
- **Summary:** When closing a reasoning block and beginning text, the code resets `thinking_block_index` and `text_block_started` but does not ensure a prior text block is stopped.
- **Concrete failure scenario:** A provider emits reasoning then text; the previous text block receives deltas after it was logically closed, producing duplicate or orphan `content_block_start` events.
- **Existing tests:** Not covered by current thinking tests.

## Coverage gaps observed

- Logging/redaction: no tests assert that prompt data or upstream error bodies are not logged.
- SSRF/URL validation: `list_models` and `/v1/upstream-models` do not have allow-list or internal-URL tests.
- Event-logging endpoint: tests are integration-only and skip by default; no unit tests for path safety or JSON repair correctness.
- Ensemble race: retry amplification, judge tie-break edge cases, and approval authorization are not exercised.
- Health endpoint: no test verifies the exact shape or information leakage.
- Conversion/response path: system-prompt injection boundaries, reasoning-tag split behavior, and namespace tool collisions are not covered.
